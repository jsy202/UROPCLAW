# 단일 6,000프레임 비교 명세

사용자 요청으로 새 평가의 입력을 한 녹화로 제한한다. 기존 전체 결과를 덮어쓰지 않는다. 입력은 기존 개발 자료의 사전 지정 첫 조건 `Town10HD_Opt_clear_v30_s101`이며, 지도·맑은 낮·차량 30대·seed 101·10Hz·600초·6,000프레임이다. 다른 녹화의 프레임을 읽거나 새로 수집하지 않는다. 실제 VLM·알림도 호출하지 않는다.

## 우선순위

1. YOLO 후보 기준과 비교해 목표 차량, 검출된 목표 출현, 기준에서 도달한 GT 가시 출현의 추가 누락이 각각 0이어야 한다.
2. 개수만 같다고 통과시키지 않고 actor/episode ID 집합을 대조한다. YOLO 자체 미검출은 별도로 표시한다.
3. 이 조건을 통과한 구성 안에서 요청 수를 비교한다. 확인/요청 지연과 무조건 통과시킨 기준을 함께 보고한다.

## 비교를 고정함

기존 28구성을 같은 한 세트에 다시 재생한다. 여기에 HSV·추적·현재 색 gate를 그대로 두고 중복 억제만 바꾸는 3구성을 추가한다. 총 31구성이다.

- track-only control: 새 track을 인접 track에 alias하지 않는다. 같은 track의 30초 cooldown은 유지한다.
- reappearance: 위 control에 더해 마지막 후보 관측 이후 1초가 넘으면 다시 요청한다. 1초는 기존 출현 정의와 맞춘 고정 운영 규칙이며, 이 세트에서 임계값을 탐색하지 않는다.
- reappearance N3: 같은 수정 dedup에 기존 N3 투표만 추가해 연속 확인 효과를 분리한다.

추적·HSV·YOLO·입력 캐시·목표 색은 바꾸지 않는다. GT는 채점에만 사용하고 필터에는 전달하지 않는다. 기존 조건은 원래 구현을 사용한다. 새 정책은 실험용 구현이며 운영 경로는 자동 교체하지 않는다.

## 증거와 한계

N1/2/3/5/7/10을 동일 dedup off 조건에서도 비교해 중복 억제와 투표의 손실을 분리한다. 연속 확인의 요청 절감도 숨기지 않는다. N1에서 도달하고 N3에서 놓친 출현의 프레임·관측 수·색상·지연을 기록하고 이미지로 저장한다.

선택과 검증을 같은 한 세트에서 수행하므로 독립 평가 자료가 없다. 이 결과는 단일 장면의 관측된 추가 손실 0을 뜻하며, 전체 자료나 모든 환경에서 무손실이라는 보장이 아니다. 저장 JPEG는 확인용이며 비교는 원본 센서 입력의 공통 검출·색상 캐시를 사용한다. 실험 날짜는 기록하지 않는다.
