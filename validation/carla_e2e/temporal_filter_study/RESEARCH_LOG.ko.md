# 실험 과정과 해결 기록

이 문서는 실제로 관측한 문제, 확인한 근거, 해결한 범위를 구분한다. 결과를 설명하기 위해 발생하지 않은 시행착오를 추가하지 않았다.

## 실행 범위의 변경

처음에는 60개 녹화와 일부 실제 VLM 검증을 계획했다. 사용자가 실제 VLM 호출을 금지해 표본 호출·실제 VLM worker 측정을 실행 목록에서 제거했고, 실행 정책과 CLI 진입점에서도 차단했다. 앞서 연결 확인용으로 실행한 이미지 1장 호출은 별도로 보존하고 본 실험에서 제외했다.

이후 사용자가 수집량 축소를 요청해 40개에서 종료했다. 70은 영상 수가 아니라 한 장면의 차량 수였다는 점을 설명했다. 완료된 40개는 72,000프레임이다. 정지 경계에서 다음 작업이 초기화됐지만 프레임·이미지는 모두 0개였고, 클라이언트를 종료해 `interrupted/`에 보존했다. 분석의 40개 녹화에는 포함하지 않았다.

축소 후 첫 지도는 3환경을 모두 비교하고, 두 번째 지도는 맑은 낮의 추가 검증으로 제한했다. 수집량만 바꾸고 개발·평가 seed 분리와 N 선택 규칙은 유지했다.

## 1. ‘3프레임’이라는 설명과 실제 구현의 차이

코드에서 3개 관측을 모아 `unknown`을 제외하고 투표하며, 판정 후 기록을 삭제하는 것을 확인했다. 연속 3회 모두 목표라는 조건도, 최근 3개를 계속 갱신하는 방식도 아니었다.

이 차이를 무시하면 관측 수 효과와 투표 규칙 효과가 섞인다. 현재 규칙과 전체 분모 2/3, 3/3, 슬라이딩 2/3을 별도 구성으로 비교했다. 현재 temporal 구현과 다른 N의 동작도 무작위 색상·간격 시퀀스로 대조했다.

## 2. CARLA 지도 로딩 충돌

Town10HD_Opt 파일럿 뒤 Town03을 로드할 때 native SIGSEGV가 발생했다. 세부 원인이 메모리인지 그래픽인지 단정할 근거는 없었다.

Town03_Opt 파일럿은 성공했다. 처음에는 실행 인자로 지도를 지정한 것이 해결책이라고 추정했지만, 본 실험 전환에서 RPC가 기본 Town10HD_Opt를 반환하는 것을 확인해 추정을 바로잡았다. 실제 성공 경로는 새 서버에서 `client.load_world('Town03_Opt')`를 호출하는 것이었다. 요청 후 실제 지도 이름까지 확인하도록 수정했다.

**해결 범위:** 사용한 Opt 지도에서는 수집을 완료했다. 원래 비최적화 Town03의 native 충돌 원인까지 해결한 것은 아니다. [상세 D01](defects/D01-map-transition.md)

## 3. 서버 wrapper가 끝나도 Unreal 자식이 남음

첫 지도의 30개 녹화를 마친 뒤 새 서버가 `Address already in use`로 종료됐다. 프로세스와 포트 상태를 확인하니 CarlaUE4.sh는 종료됐지만 소유한 Unreal 자식이 2000번 포트를 계속 점유하고 있었다.

wrapper의 종료 코드만 보던 supervisor를 수정했다. 소유 프로세스 그룹에 종료 신호를 보내고 RPC·streaming 포트가 풀렸는지 확인하며, 제한 시간 이후에도 남으면 해당 그룹을 강제 종료한다. 완료된 30개 녹화는 재수집하지 않고 나머지부터 재개했다.

**검증:** wrapper가 이미 종료됐어도 그룹 종료를 시도하는 회귀 테스트, 지도 로드 후 실제 이름을 검사하는 회귀 테스트를 추가했다. 두 번째 지도의 10개 녹화도 완료했다. [상세 D04](defects/D04-server-process-group.md)

## 4. 비교 도구가 대안 구조에 미리 색상을 알려줌

‘추적 지속성 확인 후 색상 판별’ 대안을 만들 때, 추적 입력에 기존 색상 라벨을 그대로 전달한 오류를 테스트로 발견했다. 이 경우 뒤에서 색상을 판별한다고 해도 앞단 재연결 판단에는 이미 색상이 사용된다.

대안 tracker에는 `unknown`만 전달하고 존재 확인 후 현재 검출의 색상을 읽게 고쳤다. 또한 replay 시계를 공유 모듈에 주입한 뒤 복구하지 않던 부분을 `finally`로 복원했다. 원본 production은 수정하지 않았다. [상세 D02](defects/D02-validation-isolation.md)

## 5. 정답 연결과 출현 구간이 결과를 왜곡할 수 있음

독립 리뷰에서 세 문제가 발견됐다.

- 겹치는 GT box도 최고 IoU 차량 하나로 강제 연결했다.
- 검출이 이어지면 GT가 보이지 않는 구간까지 연결돼 별개의 가시 출현이 합쳐졌다.
- COMPLETE 파일 개수만 세면 조건 중복이나 짧은 녹화를 받아들일 수 있었다.

최소 IoU 0.30, 상위 후보 차이 0.05 이하의 모호성 규칙을 정하고 후보 actor·IoU를 남겼다. GT가시 출현과 검출 출현은 독립 집계했다. 완료 검사는 정확한 조건 집합·1,800개 연속 index/센서 frame/시각·이미지 존재·actor 정리 성공까지 확인하도록 강화했다.

각 문제를 수정 전 실패하는 입력으로 재현하고 수정 후 통과를 확인했다. 원본 검출과 GT 투영이 남아 있어 평가 오류 때문에 영상을 다시 수집할 필요는 없었다. [상세 D03](defects/D03-evaluation-denominators.md)

## 6. 개발에서 고른 N2가 평가에서는 실패함

개발 16개에서는 N1과 N2의 도달 출현 수가 같았고, N2의 미연결 요청이 적었다. 사전 규칙으로 N2를 선택해 기록했다.

평가 24개에서는 N2의 도달률이 N1보다 낮아 2%p 조건을 충족하지 못했다. 평가 결과를 보고 개발 선택 파일을 바꾸지 않았다. ‘선택됐음’과 ‘새 입력에서도 검증됐음’이 다르다는 결과로 기록했다.

## 7. N3 누락의 주된 양상은 짧은 실제 관측이었음

N1에서 색상이 확인되고 N3에서는 확인되지 않은 출현 24건 중 21건의 관측 수가 1~2개였다. 한 건은 세 관측이 서로 다른 track으로 나뉘었고, 두 건은 blue보다 다른 색 표가 많았다.

이 결과는 N만 늘려 순간 오류를 줄이려는 설계가 짧은 검출 출현과 충돌함을 보여준다. 녹화 경계 1초에 걸친 구간을 빼도 N1 103/113, N3 83/113으로 차이가 남았다. 파라미터를 결과에 맞춰 다시 고르거나 production을 자동 수정하지 않았다. [추적 CSV](results/temporal_miss_diagnosis.csv)

## 8. 합성 dedup 반례와 실제 관측을 구분함

가까이 있는 파란 차량 두 대가 별도 track인데도 fragment로 묶이는 통제 반례를 재현했다. 현재 매칭된 track을 다른 track의 fragment 부모로 쓰지 않는 대안은 이 반례를 개선했다.

실제 N3 평가에서 이 대안의 고유 차량 도달률은 원래와 같았다. 따라서 실제 영상에서 확인하지 못한 개선 효과를 주장하지 않았고, 대안을 production에 적용하지 않았다.

## 보존한 근거

- 매 프레임 RGB 이미지, 원본 YOLO·HSV 출력, 시각·GT 투영·차량 도장·환경 manifest.
- 구성별 후보·억제·요청 사건과 출현별 결과.
- 개발 단계에서 고정한 N 선택, 녹화 단위 paired 신뢰구간.
- 성공 사례와 N1/N3 불일치 사례 이미지.
- 사용자 지시에 따른 실제 VLM 차단과 수집량 축소 기록.
